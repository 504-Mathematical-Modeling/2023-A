# 项目复盘与五条铁律

> 拿到题目第一天该做什么？论文写不完怎么办？本文件总结六大题型通用的项目管理铁律。
> 适用于 3 天 4 题的国赛/华数杯/MathorCup 等建模竞赛节奏。

---

## 一、3 天时间线通用规划

| 时间 | 任务 | 产出 |
|------|------|------|
| Day1 上午 | 通读题目、查文献、确定每题题型与方法 | 题型判定表 + 方法清单 |
| Day1 下午 | 建立问题一模型、写代码跑通最小可行版本 | Q1 可运行代码 + 初步结果 |
| Day1 晚 | 模型精化、跑完整数据、写问题一论文初稿 | Q1 论文初稿 + 结果表 |
| Day2 上午 | 问题二建模与求解 | Q2 代码 + 结果 |
| Day2 下午 | 问题三建模（通常规模更大或需启发式） | Q3 代码 + 结果 |
| Day2 晚 | 问题四（通常含随机性/预测/敏感性） | Q4 代码 + 结果 |
| Day3 上午 | 摘要六段、问题分析、模型假设、检验 | 全文初稿 |
| Day3 下午 | 排版、画图、检查清单、AI 声明 | 终稿 PDF |
| Day3 晚 | 预留 4 小时应急（编译错误/数据补跑） | 提交 |

> **关键节点**：Day1 晚上 Q1 必须出结果；Day2 晚上 Q2/Q3 必须出结果；Day3 中午 Q4 必须出结果。任一节点未达成，立即启动 Plan B（简化模型）。

## 二、五条铁律（六大题型通用）

### 铁律一：先结果，后论文

**原则**：所有题目先跑通最小可行模型拿到数字结果，再回头写论文。绝不能"边写边等结果"。

**反例**：
> Day1 下午开始写问题重述和问题分析，等到 Day2 才开始建模写代码，结果发现模型无解，论文已写 3 页全部作废。

**正例**：
> Day1 上午用最简单的 LP 跑通 Q1，拿到一个基准数字（哪怕粗糙）。Day1 晚上才动笔写 Q1 论文，结果已在手。

### 铁律二：保证能解

**原则**：建模时优先选择有成熟求解器/库支持的方法。复杂的非线性、NP-hard 问题先用启发式拿到可行解，再考虑精确算法。

**反例**：
> Q3 是大规模选址问题，强行上精确 MILP，Gurobi 跑 6 小时无解，全军覆没。

**正例**：
> Q3 先用贪心/遗传算法 30 秒拿到可行解（哪怕次优），再用 MILP 在小规模子问题上验证精确性，论文中对比两者。

**六大题型"保证能解"的默认方法**：

| 题型 | 默认方法（保证能出结果） | 升级方法（有时间再上） |
|------|--------------------------|------------------------|
| 优化类 | LP / MILP + Gurobi/CBC | 拉格朗日松弛、Benders 分解 |
| 预测类 | 线性回归 + ARIMA | LSTM、Prophet、XGBoost |
| 评价类 | 熵权 + TOPSIS | AHP 主观赋权、模糊综合 |
| 分类类 | K-means + 判别分析 | SVM、随机森林 |
| 统计类 | t 检验 + 方差分析 | 非参数检验、贝叶斯 |
| 机理类 | 一阶 ODE + Euler 法 | Runge-Kutta、PDE 有限元 |

### 铁律三：警惕极端值

**原则**：建模前必须做数据描述性统计（min/max/mean/median/缺失率）。极端值可能是数据错误，也可能是题目陷阱。

**反例**：
> 预测类题目，未做异常值检测直接回归，某天数据为 0（实为缺失填 0），导致 ARIMA 预测全负，论文结论反向。

**正例**：
> 建模前画箱线图，发现 3 个异常值，用 3σ 准则剔除并说明，回归 R² 从 0.45 提升到 0.82，论文中专门加一段"数据预处理"。

### 铁律四：参数合理

**原则**：所有模型参数必须有来源（题目给定 / 文献引用 / 合理假设 + 灵敏度分析）。不能凭空取值。

**反例**：
> 评价类题目，AHP 判断矩阵元素"凭感觉"填，一致性比率 CR=0.35 > 0.1，整张矩阵作废。

**正例**：
> AHP 判断矩阵基于"参考文献[3]的专家打分"构建，CR=0.05 < 0.1 通过一致性检验；同时对权重做 ±20% 灵敏度分析，证明排序稳健。

### 铁律五：摘要六段法

**原则**：摘要必须分六段（背景+总方法 / Q1 / Q2 / Q3 / Q4 / 总结），每段必须含具体方法名 + 具体数值结果。详见 `摘要六段法通用规范.md`。

**反例**（空洞摘要）：
> 本文针对 XX 问题，建立了优化模型，得到了较好的结果，具有一定指导意义。

**正例**（含数值）：
> 针对问题一，建立以总成本最小为目标的 MILP 模型，含库存平衡、产能、逻辑三类约束，用 Gurobi 求解得到最优成本 **152340 元**，较贪心算法下降 **12.3%**。

## 三、文件组织建议

```
我的竞赛项目/
├── 代码/
│   ├── Q1_milp.py
│   ├── Q2_extend.py
│   ├── Q3_heuristic.py
│   ├── Q4_simulation.py
│   └── utils/              # 公用函数：数据加载、画图
├── 数据/
│   ├── raw/                # 原始数据，只读
│   └── processed/          # 清洗后数据
├── 图表/
│   ├── fig1_framework.png
│   └── ...
├── 文献/                   # PDF 文献
├── 论文/
│   ├── main.tex
│   └── refs.bib
└── 日志.md                 # 每日进度记录
```

**命名规范**：代码文件 `Q{n}_{方法}.py`，图表 `fig{n}_{含义}.png`，保证论文引用时一目了然。

## 四、常见翻车场景与对策

| 翻车场景 | 对策 |
|----------|------|
| Gurobi 无学术版授权 | 用 CBC / PuLP / SCIP 替代，结果相差 < 1% |
| 数据量太大 Python 跑不动 | 用 numpy 向量化，或转 PyPy，或采样后建模 |
| LaTeX 编译报错找不到图 | 建一个 `figures/` 文件夹，路径统一写 `figures/fig1_xxx.png` |
| 摘要写超字数 | 优先删背景段套话，保留每个 Q 的方法名 + 核心数字 |
| 模型无解 | 检查约束矛盾 → 放松约束（大 M 调小）→ 改为目标规划 |

---

## 五、一句话总结

> **先有结果再写论文，简单模型先跑通，复杂模型后优化，参数有据可查，摘要六段不空话。**
